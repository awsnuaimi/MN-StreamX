# MN StreamX — إصلاح فشل اختبارات #137 بعد تحديث الشعار

## السبب المرجح

حزمة الشعار السابقة استبدلت `app/src/main/AndroidManifest.xml` بنسخة أقدم. هذا قد يكون قد حذف تعريفات `provider` اللازمة لمشاركة التقارير وتثبيت APK. لا يمكن معرفة أسماء الـProviders الدقيقة من النسخ المتاحة؛ لذا **لا يتم اختراع أي أسماء أو صلاحيات**.

## طريقة التطبيق على GitHub

1. أضف الملفين الموجودين في هذه الحزمة إلى المستودع الحالي، بالمواقع نفسها، دون حذف أي ملفات أخرى.
2. افتح `GitHub → Actions → Repair manifest providers (one-time) → Run workflow` واختر الفرع `main`.
3. ستبحث العملية في تاريخ ملف الـManifest السابق، وتعيد تعريفات الـProviders المفقودة فقط، مع الحفاظ على شعار MN StreamX الجديد.
4. ستنفّذ `testDebugUnitTest` قبل إنشاء أي Commit. إن فشلت الاختبارات لن تُدفع التعديلات تلقائيًا.
5. إن نجحت الاختبارات، سيُنشأ Commit لإصلاح Manifest، وعندها سيبدأ مسار `Build APK` المعتاد.

## متطلبات وحدود

- يحتاج Workflow إذن `contents: write` وأن تسمح إعدادات المستودع لـGitHub Actions بالكتابة على `main`؛ قيود حماية الفرع قد تمنع الدفع.
- إن لم يعثر السكربت على تعريفات Providers في تاريخ Git فسيُوقف العملية دون تغيير الملف. في هذه الحالة ينبغي استرجاع الـManifest الأصلي عبر History ثم تغيير `android:banner` فقط.
- قد يستمر الفشل لأسباب أخرى؛ يتم التحقق بالاختبارات الفعلية قبل حفظ أي إصلاح.
- لا تغيّر ملفات Kotlin أو القنوات أو EPG أو إعدادات التوقيع.
